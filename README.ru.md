# astv

[English](README.md) | [Русский](README.ru.md)

Текущая версия: `0.2.0`.

`astv` — консольный монитор Asterisk Manager Interface (AMI) для Linux,
написанный на C. Показывает каналы, пиры/ендпоинты и события АТС в реальном
времени. Утилита предназначена для наблюдения: она не создаёт, не переводит
и не завершает звонки.

## Возможности и интерфейс

Экран разделён на четыре панели:

| Панель | Содержимое |
| --- | --- |
| Верхняя левая | Все активные каналы АТС |
| Верхняя правая | Пиры SIP/IAX2 и ендпоинты PJSIP |
| Нижняя левая | Общая лента отображаемых событий AMI |
| Нижняя правая | События выбранного канала |

Левая колонка занимает 3/5 ширины, правая — 2/5. Верхний ряд занимает
3/4 высоты. Количество звонков определяется по уникальным `Linkedid`;
при отсутствии этого поля используется `Uniqueid`.

Поддерживаются `chan_sip`, `chan_pjsip` и `chan_iax2`, отображаются изменения
регистрации. При запуске запрашиваются каналы, пиры, ендпоинты, контакты PJSIP
и сведения о регистрации. Создание канала, набор, изменение состояния,
изменение моста и завершение разговора автоматически планируют обновление
пиров с задержкой в одну секунду для объединения серии событий.
`DeviceStateChange` обновляет соответствующую запись сразу. При исходящих
звонках используются `Channel` и `DestChannel`, чтобы отметить устройство
и транк как `In use` до следующего полного обновления.

Пиры сортируются по имени без учёта регистра, поэтому изменение статуса
не переставляет строки. Новые списки собираются отдельно от отображаемых;
при ошибке источника сохраняются его последние известные записи.

Перерисовываются изменившиеся панели. При выходе восстанавливаются
настройки терминала и содержимое экрана, видимое до запуска утилиты.

## Совместимость с Asterisk

При каждом входе в AMI запрашивается `CoreSettings`, откуда считываются
`AsteriskVersion` и `AMIversion`. Версия определяет набор запросов, а ответы
AMI позволяют учитывать недоступные действия и отключённые модули.

| Профиль | Получение каналов и мостов |
| --- | --- |
| Asterisk 16 | `CoreShowChannels`, отдельный запрос контактов PJSIP |
| Asterisk 18 | `CoreShowChannels`, дополнение через `Status` с 18.26 |
| Asterisk 20 | `CoreShowChannels`, дополнение через `Status` с 20.11 |
| Asterisk 22 | `CoreShowChannels`, дополнение через `Status` с 22.1 |

`Status.BridgeID` дополняет `CoreShowChannel.BridgeId`, а события
`BridgeEnter` и `BridgeLeave` поддерживают актуальность столбца BRIDGE.
Количество ендпоинтов и контактов уточняется по завершающим событиям списков.
Если отдельный запрос контактов недоступен, используется поле `Contacts`
в списке ендпоинтов, когда сервер его предоставляет. Если версия не определена,
после небольшого тайм-аута выполняются запросы с проверкой ответов.

Это реализованные профили совместимости, а не утверждение о тестировании
каждой сборки Asterisk и каждого дистрибутива.

## Требования

- Linux, компилятор C11, `make`, стандартные заголовки Linux/POSIX.
- Поддержка POSIX threads; сборка использует `-pthread`.
- Терминал от 72 столбцов и 16 строк, UTF-8 и шрифт с Unicode-псевдографикой.
- Доступ к AMI и учётная запись с необходимыми разрешениями.
- Права root для запуска мониторинга. `--help` доступен без root.

Сторонних библиотек времени выполнения нет; ncurses не используется.
Для старых систем рекомендуется сборка на целевом дистрибутиве: готовый
бинарник не гарантирует совместимость со всеми версиями glibc.

## Сборка и установка

Debian/Ubuntu:

```sh
sudo apt install build-essential
```

AlmaLinux/Rocky Linux/Fedora:

```sh
sudo dnf install gcc make glibc-devel
```

В каталоге исходных текстов:

```sh
make
make test
sudo ./astv
```

Необязательная установка в системный каталог:

```sh
sudo install -m 0755 astv /usr/local/bin/astv
sudo astv
```

Цели `make install` нет. Для очистки результатов сборки используйте
`make clean`. Для удаления установленной программы удалите
`/usr/local/bin/astv`; конфигурация `/etc/astv/astv.conf` удаляется отдельно.

## Настройка Asterisk

Пример `/etc/asterisk/manager.conf` для локального подключения:

```ini
[general]
enabled = yes
port = 5038
bindaddr = 127.0.0.1

[astv]
secret = replace-with-a-long-random-secret
read = system,call,reporting,command
write = system,call,reporting
permit = 127.0.0.1/255.255.255.255
```

Замените пароль и примените настройки:

```sh
asterisk -rx "manager reload"
asterisk -rx "manager show users"
```

Права `write` нужны для выполнения действий AMI, в том числе запросов
снимков состояния. Сама утилита не изменяет звонки. Доступность действий
также зависит от загруженных модулей Asterisk.

В примере пользователь называется `astv`, а мастер настройки предлагает
`monitor` по умолчанию. При использовании примера введите имя `astv`.
Правила `permit` и адрес прослушивания меняйте с учётом вашей сети.

Клиент использует обычный TCP и не поддерживает AMI TLS напрямую.
Не публикуйте открытый порт AMI в Интернет; для удалённого подключения
используйте VPN или SSH-туннель.

## Первый запуск и конфигурация

```sh
sudo ./astv
```

По умолчанию читается `/etc/astv/astv.conf`. Если файл отсутствует,
интерактивный мастер запросит адрес (`127.0.0.1`), порт (`5038`), имя
пользователя (`monitor`) и пароль AMI. Ввод пароля скрывается.
Файл создаётся с правами `0600`.

Пример конфигурации:

```ini
host=127.0.0.1
port=5038
username=astv
secret=replace-with-a-long-random-secret
```

При отсутствии конфигурации и интерактивного терминала программа завершится
с ошибкой. Сначала выполните настройку интерактивно либо укажите готовый файл.
Соединение и аутентификация выполняются до открытия TUI. При ошибке программа
выводит сообщение в stderr и завершается с кодом `1`.

## Параметры запуска

| Параметр | Назначение |
| --- | --- |
| `-H`, `--host HOST` | Адрес AMI |
| `-p`, `--port PORT` | Порт AMI |
| `-u`, `--user USER` | Имя пользователя AMI |
| `-s`, `--secret-file FILE` | Прочитать пароль из файла |
| `-c`, `--config FILE` | Другой конфигурационный файл |
| `-h`, `--help` | Справка без подключения к AMI |

Сначала загружается конфигурация, затем применяются параметры адреса, порта
и пользователя. Переменная `ASTV_SECRET` заменяет пароль из конфигурации,
а `--secret-file` имеет приоритет над обоими источниками. Эти изменения
не сохраняются. Отсутствие файла конфигурации вызывает мастер даже при
заданных параметрах переопределения.

Передача пароля через окружение при использовании sudo:

```sh
sudo env ASTV_SECRET='replace-with-a-long-random-secret' ./astv \
  --host 127.0.0.1 --user astv
```

Либо через отдельный защищённый файл:

```sh
printf '%s\n' 'replace-with-a-long-random-secret' > ~/.astv-secret
chmod 600 ~/.astv-secret
sudo ./astv --user astv --secret-file ~/.astv-secret
```

Пароли в командах могут сохраняться в истории оболочки. Для постоянной
настройки предпочтителен защищённый конфигурационный файл.

## Управление

| Клавиша | Действие |
| --- | --- |
| `Tab` / `Shift+Tab` | Следующая / предыдущая панель |
| `↑` / `↓` | Перемещение по строкам активной панели |
| `PgUp` / `PgDown` | Перемещение на страницу |
| `←` / `→` | Горизонтальная прокрутка выбранной строки |
| `Home` / `End` | Первая / последняя запись |
| `h` | Открыть или закрыть справку |
| `Esc` | Закрыть справку |
| `q` | Выход; игнорируется при открытой справке |

Если список длиннее панели, появляется полоса прокрутки. В лентах событий
курсор на последней записи следует за новыми событиями. Перемещение вверх
приостанавливает слежение до возвращения в конец списка. Символы `<` и `>`
показывают скрытый текст слева и справа.

В справке продолжаются мониторинг и приём событий. Её содержимое можно
листать стрелками вверх/вниз. Та же информация доступна через `./astv --help`.

## Обозначения заголовков

| Обозначение | Значение |
| --- | --- |
| `CH:N` | Количество каналов |
| `CL:N` | Количество звонков, сгруппированных по Linkedid |
| `AST:V` | Обнаруженная версия Asterisk |
| `[+]` | AMI подключён |
| `[!]` | Соединение прервано, ожидание повтора |
| `[?]` | Переподключение или вход в AMI |
| `PEERS: N` | Общее количество записей SIP/IAX2/PJSIP |
| `SIP:s/N` | Результат запроса SIP и количество пиров |
| `IAX2:s/N` | Результат запроса IAX2 и количество пиров |
| `PJSIP:+ E:N C:N` | Запрос ендпоинтов успешен, число ендпоинтов и контактов |
| `PJSIP:-` / `PJSIP:?` | Ошибка / ожидание запроса ендпоинтов |

Для статуса запроса `+` означает успех, `-` — ошибку, `?` — ожидание.
Вместо количества контактов также может выводиться статус `-` или `?`.
Ошибка SIP на сервере только с PJSIP сама по себе не является неисправностью.

## Переподключение и ограничения

При потере установленного соединения программа сохраняет последний экран
и выполняет до трёх попыток переподключения с паузами по три секунды.
Если все попытки неудачны, появляется модальное предупреждение с выходом по `q`.
Пауза между попытками не включает время DNS/TCP-подключения и входа в AMI.

В памяти хранится до 1024 каналов, 1024 пиров/ендпоинтов и 4096 событий.
При заполнении истории старые события вытесняются. История не записывается
на диск и не сохраняется после выхода. Из ленты исключены события снимков
каналов и RTCP. После переподключения загружается текущее состояние, но события,
пропущенные во время обрыва, восстановить нельзя.

## Удалённое подключение через SSH

```sh
ssh -N -L 15038:127.0.0.1:5038 user@asterisk-server
```

В другом терминале:

```sh
sudo ./astv --host 127.0.0.1 --port 15038
```

Порт `15038` выбран, чтобы не конфликтовать с локальным AMI на `5038`.
Туннель должен оставаться запущенным во время мониторинга.

## Диагностика

- Отказ или тайм-аут соединения: проверьте адрес, порт, `enabled`, firewall
  и состояние SSH-туннеля.
- Ошибка входа: проверьте имя пользователя, пароль и правило `permit`.
- `-` в диагностике протокола: проверьте разрешения AMI, загруженные модули
  и доступность соответствующего действия на этой версии Asterisk.
- Некорректные рамки: проверьте UTF-8, шрифт и размеры терминала.
- Ошибка прав запуска: используйте `sudo`; справка root не требует.

## Структура исходных текстов

- `src/main.c`: сеанс AMI, снимки пиров, интерфейс, клавиатура и цикл событий.
- `src/ami.c`: потоковый разбор сообщений AMI.
- `src/asterisk_compat.c`: версии и совместимость AMI.
- `src/channel_store.c`: состояние каналов и подсчёт звонков.
- `src/connection.c`: фоновые попытки DNS/TCP-подключения.
- `src/config.c`: чтение, проверка и атомарное сохранение конфигурации.
- `include/`: интерфейсы модулей и версия программы.
- `tests/test.c`: регрессионные тесты; запуск через `make test`.
